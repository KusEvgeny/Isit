# Документация REST API «Система учёта офисного оборудования» (с авторизацией)

Базовый адрес: `http://localhost:8000`. Формат данных: JSON (UTF-8). Все адреса начинаются с `/api`.
Запуск: `cd lab9/src && docker compose up -d && php bin/reset-db.php && php -S localhost:8000 -t public`. Клиентское приложение: `http://localhost:8000/client/`. Данные хранятся в PostgreSQL (база `taskapp`).

API дополнено: данные в PostgreSQL, вход по токену, проверка прав по ролям, пароли сотрудников.

## Авторизация

Все адреса, кроме `POST /api/auth/login`, требуют заголовок:
`Authorization: Bearer <токен>`

Токен выдаётся при входе, действует 2 часа и перестаёт действовать после выхода. Без заголовка, с неверным или просроченным токеном сервер отвечает `401`; если токен действует, но роли не хватает, — `403`.

### Роли и права

| Действие | manager (руководитель) | user (сотрудник) |
|----------|:---:|:---:|
| смотреть оборудование | да | да |
| создавать и изменять оборудование (`POST`, `PUT`, `PATCH`) | да | да |
| удалять оборудование (`DELETE`) | да | нет, 403 |

Тестовые сотрудники (пароль у всех `123456`): `anna@example.com` — manager, `igor@example.com` — user.

## Сводная таблица

| Метод | URL | Назначение | Кто может | Успешный код |
|-------|-----|------------|-----------|--------------|
| POST | `/api/auth/login` | вход: email и пароль → токен | все (без токена) | 200 |
| GET | `/api/auth/me` | кто вошёл по этому токену | вошедший | 200 |
| POST | `/api/auth/logout` | выход: токен перестаёт действовать | вошедший | 204 |
| GET | `/api/equipment` | список оборудования | вошедший | 200 |
| GET | `/api/equipment/{id}` | оборудование по номеру | вошедший | 200 |
| POST | `/api/equipment` | добавить оборудование | вошедший | 201 |
| PUT, PATCH | `/api/equipment/{id}` | изменить оборудование | вошедший | 200 |
| DELETE | `/api/equipment/{id}` | удалить оборудование | manager | 204 |

## Общие правила и коды ответа

- Тело запросов `POST`, `PUT`, `PATCH` — JSON-объект.
- Ошибки возвращаются в едином формате: `{"error": "текст"}`, а для ошибок проверки ещё и `"errors": {"поле": "текст"}`.

| Код | Когда |
|-----|-------|
| 200, 201, 204 | успех |
| 400 | тело запроса — не корректный JSON |
| 401 | нет токена, неверный пароль |
| 403 | роль не позволяет действие |
| 404 | нет записи или адреса |
| 422 | данные не прошли проверку |
| 503 | база данных недоступна |

## Вход и выход

### POST /api/auth/login — вход

Запрос:
```http
POST /api/auth/login
Content-Type: application/json

{ "email": "anna@example.com", "password": "123456" }
```

Ответ `200 OK`:
```json
{
    "token": "d6c99ce91e…(64 символа)",
    "expires_at": "2026-10-27T20:51:55+00:00",
    "user": { "id": 1, "name": "Анна Петрова", "email": "anna@example.com", "role": "manager" }
}
```
Ошибки: `401` (`{"error": "Неверный email или пароль"}`), `422` (пустые поля), `400` (не JSON).

### GET /api/auth/me — кто вошёл
Запрос: `GET /api/auth/me` с токеном.
Ответ `200 OK`: `{ "id": 1, "name": "Анна Петрова", "role": "manager" }`.

### POST /api/auth/logout — выход
Запрос: `POST /api/auth/logout` с токеном. Ответ `204 No Content`.

## Ресурс «Оборудование»

Поля: `id` (число), `category_id` (число), `employee_id` (число или null), `inventory_number` (строка, уникальная), `title` (строка), `status` (`in_use`, `in_repair`, `archived`).

### GET /api/equipment — список
Ответ `200 OK`:
```json
[
    { "id": 1, "category_id": 1, "employee_id": 1, "inventory_number": "INV-001", "title": "Компьютер Lenovo", "status": "in_use" }
]
```

### GET /api/equipment/{id} — по номеру
Запрос: `GET /api/equipment/3`.
Ответ `200 OK`: объект оборудования. Ошибка: `404` (`{"error": "Оборудование не найдено"}`).

### POST /api/equipment — создание
Запрос:
```http
POST /api/equipment
Authorization: Bearer <токен>

{ "title": "МФУ Canon", "inventory_number": "INV-005", "category_id": 3, "status": "in_use" }
```
Ответ `201 Created`: объект оборудования с новым `id`.
Ошибки: `422` (ошибки полей), `400`.

### PATCH /api/equipment/{id} — изменение
Запрос: `PATCH /api/equipment/5` с телом `{ "status": "in_repair" }`.
Ответ `200 OK`: обновлённый объект. Ошибки: `404`, `422`.

### DELETE /api/equipment/{id} — удаление
Только `manager`. Ответ `204 No Content`. Ошибки: `403`, `404`.
