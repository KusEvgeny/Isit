# Лабораторная работа №7
## Проектирование REST API

### Цель работы

Изучить принципы проектирования REST API, разработать набор ресурсов информационной системы, реализовать основные HTTP-методы, подготовить документацию API и выполнить тестирование запросов.

---

## Краткое описание выполненного задания

На основе серверной части из лабораторной работы №6 («Система учёта офисного оборудования», PHP 8.2, MVC) реализован REST API с тремя ресурсами: оборудование, сотрудники, категории. Для каждого ресурса поддержаны операции CRUD через методы `GET`, `POST`, `PUT`/`PATCH`, `DELETE`; ответы возвращаются в формате JSON с корректными кодами состояния (200, 201, 204, 400, 404, 405, 409, 422, 500). Сайт из лабораторной работы №6 продолжает работать.

## Описание реализованных ресурсов

| Ресурс | URL | Методы | Назначение | Формат данных |
|--------|-----|--------|------------|---------------|
| Оборудование | `/api/equipment`, `/api/equipment/{id}` | GET, POST, PUT/PATCH, DELETE | учёт офисного оборудования | `id, employee_id, number, title, category, status` |
| Сотрудники | `/api/employees`, `/api/employees/{id}`, `/api/employees/{id}/equipment` | GET, POST, PUT/PATCH, DELETE | сотрудники и их оборудование | `id, name, position` |
| Категории | `/api/categories`, `/api/categories/{id}` | GET, POST, PUT/PATCH, DELETE | справочник категорий | `id, name` |

Адреса — существительные во множественном числе; действие определяется HTTP-методом; связь «сотрудник — его оборудование» выражена вложенным адресом; фильтры передаются строкой запроса (`?status=in_use&employee_id=1`).

## Описание REST API

Полная документация с параметрами, примерами запросов и ответов: [docs/api.md](./docs/api.md). Сводная таблица:

| Метод | URL | Назначение | Успешный код |
|-------|-----|------------|--------------|
| GET | `/api/equipment` | список оборудования (`status`, `employee_id`) | 200 |
| GET | `/api/equipment/{id}` | оборудование по номеру | 200 |
| POST | `/api/equipment` | создать оборудование | 201 |
| PUT, PATCH | `/api/equipment/{id}` | изменить оборудование | 200 |
| DELETE | `/api/equipment/{id}` | удалить оборудование | 204 |
| GET, POST | `/api/employees` | список / создание сотрудника | 200 / 201 |
| GET, PUT, PATCH, DELETE | `/api/employees/{id}` | сотрудник: чтение, изменение, удаление (409, если есть оборудование) | 200 / 204 |
| GET | `/api/employees/{id}/equipment` | оборудование сотрудника | 200 |
| GET, POST | `/api/categories` | список / создание категории | 200 / 201 |
| GET, PUT, PATCH, DELETE | `/api/categories/{id}` | категория: чтение, изменение, удаление | 200 / 204 |

Устройство реализации:
- маршруты `routes/web.php`; маршрутизатор `Router` поддерживает `get, post, put, patch, delete` и сам возвращает JSON-ответы 404 и 405 (с заголовком `Allow`) для адресов `/api/...`;
- контроллеры `app/Controllers/Api/`: по пять методов `index, show, store, update, destroy`; `PUT` и `PATCH` обрабатываются одним методом `update` (присланные поля заменяют старые);
- модели наследуют от `JsonRepository` (`all, find, add, update, delete`), данные в `storage/*.json`;
- помощники `json_response()`, `json_error()`, `no_content()`, `json_input()` в `app/helpers.php`;
- данные проверяются на сервере (`validate()`), ошибки возвращаются все сразу в формате `{"error": "...", "errors": {"поле": "..."}}`.

## Примеры запросов и ответов

**Создание оборудования** (`POST /api/equipment`):
```http
POST /api/equipment
Content-Type: application/json

{ "title": "Тестовый монитор", "number": "INV-555", "category": "monitor", "status": "in_use", "employee_id": 1 }
```
```http
HTTP/1.1 201 Created
Location: /api/equipment/9

{ "id": 9, "employee_id": 1, "number": "INV-555", "title": "Тестовый монитор", "category": "monitor", "status": "in_use" }
```

**Ошибка проверки** (`POST /api/equipment` с телом `{"title":"ab","number":"INV-111"}`), код 422:
```json
{
    "error": "Ошибка проверки данных",
    "errors": {
        "title": "Название — не короче 3 символов"
    }
}
```

**Изменение** (`PATCH /api/equipment/9`, тело `{"status": "in_repair"}`): код 200, меняется только статус.
**Удаление** (`DELETE /api/equipment/9`): код 204, тела нет; повторное удаление — 404.
**Метод не поддержан** (`DELETE /api/categories`): код 405, `Allow: GET, POST`.
**Конфликт** (`DELETE /api/employees/1`, у сотрудника есть оборудование): код 409.

## Вывод

В результате работы спроектированы три ресурса информационной системы и реализован REST API на PHP: адреса строятся по правилам REST, действия задаются HTTP-методами, поддерживаются все операции CRUD, данные передаются в JSON, а результат сообщается кодами состояния 200, 201, 204, 400, 404, 405, 409 и 422. Серверная проверка входных данных и единый формат ошибок облегчают работу клиентского приложения, а документация (`docs/api.md`) и таблица тестирования (`docs/testing.md`) позволяют воспроизвести и проверить каждый запрос. Структура «маршрут — контроллер — модель» из лабораторной работы №6 позволяет заменить файловое хранилище базой данных, не меняя контроллеры.
